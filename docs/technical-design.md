# DeepSeek API 版 · 技术设计文档

本文档描述「DeepSeek API 版」桌面/移动 Web 客户端的技术方案：如何用官方账号接入、如何按 API 计费、如何把官方导出的数据完整还原为可继续对话的会话，以及如何把界面还原到与 DeepSeek 官方 App 一致的观感。文档面向参与开发与评审的工程师，读完后应能判断架构是否可行、边界是否清楚、风险是否可控。

## 方案结论与范围

### 一句话方案

采用 **纯前端 + 本地优先** 的单页应用：React + TypeScript 构建界面，对话数据全部存在浏览器 IndexedDB 中，模型能力通过 **OpenAI 兼容的 DeepSeek 官方 API** 直连，按官方 API 余额计费；同时提供一条实验性的「网页会话令牌」通道，用于没有 API Key 时以官方网页账号登录。官方导出的数据包在本地解析、归一化后写入同一个会话库，历史消息与新建消息共用一套数据结构，因此「导入即可续聊」。

### 四个关键决策

| 决策点 | 选择 | 理由与代价 |
| --- | --- | --- |
| **数据存放位置** | 浏览器 IndexedDB，全量本地 | 不上传服务器，隐私成本最低、可离线浏览历史；代价是多端同步需要自己导出/导入，浏览器清理站点数据会丢库。 |
| **模型接入方式** | 官方 API（优先）+ 网页令牌通道（实验） | API 通道稳定、可计费、有明确的错误码；网页通道依赖非公开接口，随时可能变动，作为降级手段而非主路径。 |
| **导入数据形态** | 解析官方导出包，归一化为统一消息模型 | 不重建「像官方」的临时视图，而是直接落库；导入后的会话与原生会话权限、操作完全一致。 |
| **界面还原粒度** | 布局、间距、圆角、配色、交互节奏 1:1 对齐；品牌素材不使用官方 Logo 与图标资源 | 能保持「就是这个 App」的熟悉感，同时不复制官方商标与受版权保护的图形资源，降低开源分发风险。 |

### 范围边界

- **本次交付**：会话列表与对话主流程、流式输出、深度思考内容折叠、会话搜索与重命名、官方导出包导入与续聊、用量与费用估算、设置项、明暗主题、移动端适配。
- **不在本次内**：多端云同步服务端、团队协作与分享、图片/文件上传解析、语音输入、私有化模型接入。这些在架构上预留了扩展点（见第 11 节）。

## 系统架构

### 分层结构

整体分为四层，层间只通过明确定义的接口通信，便于把「传输通道」单独替换而不影响界面与数据。

| 层 | 职责 | 主要实现 |
| --- | --- | --- |
| **视图层** | 页面结构、会话列表、消息渲染、输入框、设置页；不含网络与存储逻辑 | React 组件 + Tailwind |
| **状态层** | 会话/消息的增删改、流式片段合并、当前选中会话、UI 开关 | Zustand store |
| **领域层** | 消息上下文裁剪、导入归一化、用量与费用计算、导出 | 纯函数模块 |
| **基础设施层** | IndexedDB 读写、官方 API 与网页通道、密钥加解密 | Dexie / fetch / WebCrypto |

### 运行形态

- 标准形态是 **浏览器 Web 应用**，由静态站点托管，无后端。
- 需要「装成 App」时用 PWA 安装到桌面/主屏，读写仍在本地；也可用 Capacitor 打包成 Android/iOS 壳，架构不变，只需替换存储适配层。
- CORS 说明：DeepSeek API 支持跨域直连；若部署环境被中间层拦截，可在设置中填写自建反向代理地址作为基址。

## 技术选型

| 能力 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | React 18 + TypeScript 5 + Vite 5 | 流式更新频繁，需要细粒度重渲染控制；Vite 提供秒级冷启动，产物为纯静态文件。 |
| 样式 | Tailwind CSS 3 + CSS 变量 | 用设计令牌统一颜色与圆角，明暗主题只切换变量；避免为了「像」而复写大段 CSS。 |
| 状态 | Zustand | 比 Context 更少的重渲染，不需要 Provider 嵌套；store 可被非 React 代码调用。 |
| 本地库 | Dexie 4（IndexedDB） | 提供索引、事务与版本迁移；单库可容纳数十万条消息，避免 localStorage 的 5MB 限制。 |
| 消息渲染 | react-markdown + remark-gfm + rehype-katex + highlight.js | 表格、公式、代码高亮是编程问答的高频场景；渲染结果用 memo 缓存，避免流式时整段重排。 |
| 图标 | lucide-react | 线条风格与官方观感接近，且为开源许可，不引入官方图形资源。 |

## 数据模型与本地存储

### 实体定义

| 实体 | 关键字段 | 约束 |
| --- | --- | --- |
| Conversation | id、title、createdAt、updatedAt、model、pinned、archived、source、messageCount | id 优先沿用官方导出中的原始 id，保证重复导入可幂等去重；source 标记 native / imported。 |
| Message | id、conversationId、role、content、reasoning、status、tokens、createdAt、parentId | 一条消息一条记录；流式期间 status 为 streaming，结束后落盘为 done，异常为 error。 |
| Setting | key、value | 单行键值表，含模型、采样参数、主题、代理基址、价格表。 |
| UsageLog | id、conversationId、model、promptTokens、completionTokens、cost、at | 用于费用估算与趋势展示，按天聚合查询。 |

### 库结构与迁移

```typescript
db.version(1).stores({
  conversations: 'id, updatedAt, pinned, archived, source',
  messages: 'id, conversationId, createdAt, [conversationId+createdAt]',
  settings: 'key',
  usage: '++id, at, conversationId',
});

db.version(2).stores({
  messages: 'id, conversationId, createdAt, [conversationId+createdAt], status',
});
```

消息按 $[conversationId+createdAt]$ 建复合索引，打开会话时只读当前会话的连续区间，避免全表扫描。版本升级用 Dexie 的 **version().upgrade()** 做字段补齐，不删除用户数据。

### 容量与清理

- 单条消息正文按字符计，10 万条消息约 200–400 MB，接近浏览器配额上限，因此提供「按时间归档」与「导出后清理」两个入口。
- 启动时用 **navigator.storage.estimate()** 读取已用配额，占用超过 70% 时在设置页提示导出备份。
- 持久化申请：调用 **navigator.storage.persist()**，降低被系统回收的概率。

## 认证与鉴权

### 两种登录通道

| 通道 | 凭证来源 | 计费与额度 | 稳定性 |
| --- | --- | --- | --- |
| **API Key（主）** | 用户在官方开放平台创建，形如 **sk-** 前缀的密钥 | 走 API 余额，可在应用内查询余额与估算单次费用 | 官方公开接口，契约稳定，有明确错误码 |
| **网页令牌（实验）** | 用户在官方网页登录后，从浏览器存储中取得本人会话令牌，粘贴到应用 | 走网页账号额度，不产生 API 账单 | 依赖非公开接口，可能随官方改版失效，失败时提示切回 API Key |

两条通道在领域层被抽象为同一个 **Transport** 接口，只有 **send()** 的实现不同，界面与数据层不感知通道差异。启动时若两种凭证都存在，默认使用 API Key，用户可在设置页显式切换。

### 密钥本地加密

绝不把明文密钥写进 localStorage。首次写入时用 WebCrypto 生成不可导出的 AES-GCM 密钥，存于 IndexedDB 的非导出句柄；密文与随机 IV 一并保存。读取只在发起请求前解密到内存变量，不写入状态持久层。

```typescript
const key = await crypto.subtle.generateKey(
  { name: 'AES-GCM', length: 256 },
  false,                       // 不可导出
  ['encrypt', 'decrypt']
);
const iv = crypto.getRandomValues(new Uint8Array(12));
const cipher = await crypto.subtle.encrypt(
  { name: 'AES-GCM', iv }, key, new TextEncoder().encode(apiKey)
);
```

### 凭证校验与失效处理

- 保存前调用 **GET /user/balance** 做一次轻量校验，返回 401 直接提示「密钥无效」，不写入库。
- 运行中遇到 401：清空内存凭证、保留密文并标记为 invalid，界面切到登录页，提示「密钥已失效或被删除」。
- 网页令牌遇到 401/403：提示「网页会话已过期，请重新登录」，并保留 API Key 通道的可用性。

### 安全清单

- 所有请求只发往官方域名或用户自填的代理基址，不做任何第三方上报。
- 不记录请求头到日志；调试日志默认关闭，开启时对密钥做掩码。
- 导出文件由用户主动触发，导出内容不含密钥与令牌。
- README 与首次启动页明确提示：本项目为非官方客户端，密钥仅存于本机，泄露风险由使用者自担。

## 对话链路

### 请求构造

发送时从当前会话取最近若干轮消息，转换为官方接口的 **messages** 数组；系统提示词优先使用会话级设置，其次全局设置。历史裁剪按 token 预算而非条数：从最新往旧累计，超出预算即停止，并保证首条为 system。

```typescript
POST https://api.deepseek.com/chat/completions
{
  "model": "deepseek-chat",        // 或 deepseek-reasoner
  "messages": [{ "role": "user", "content": "..." }],
  "stream": true,
  "temperature": 0.7,
  "max_tokens": 4096
}
```

### 流式解析

用 fetch + ReadableStream 手动切 SSE，而不是 EventSource：EventSource 不支持 POST 与自定义请求头。逐块解码后按行缓冲，遇到空行视为一条事件结束，取 **data:** 后的 JSON；**[DONE]** 结束循环。

- 正文增量写入 **delta.content**，思考增量写入 **delta.reasoning_content**，两条通道分别累积，避免思考内容混进最终回答。
- 每收到片段只更新当前消息的内存缓冲，**节流 100ms** 批量提交到 store，降低重渲染次数。
- 流结束或用户点「停止」时统一落库一次，写入最终正文、token 用量与状态。
- 异常中断（网络断开）保留已生成内容，状态置为 interrupted，允许「继续生成」。

### 思考内容的呈现

深度思考模式下，回答上方出现可展开区域，标题为「已深度思考」，展开后按段落呈现推理过程，默认折叠。折叠状态不写入数据库，仅作为组件内部状态，避免污染数据。

### 重试与错误码

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 401 | 密钥无效 | 清空内存凭证，跳登录页，不自动重试 |
| 402 | 余额不足 | 提示余额不足并给充值入口链接，停止发送 |
| 429 | 限流 | 指数退避重试 2 次（1s、3s），仍失败则提示稍后再试 |
| 5xx | 服务端异常 | 保留草稿，支持一键重发 |

### 用量与费用

官方在流式最后一帧返回 usage（含 prompt_tokens、completion_tokens）。若某次请求未返回，则用本地启发式估算（中文按 1 字≈0.6 token、英文按 4 字符≈1 token）并在界面标注「估算」。费用按可配置价格表计算，设置页允许用户按官方最新价格自行调整，默认值只作示例。

## 官方数据导入与续聊

### 导出包形态

官方数据导出通常是一个压缩包，内含一份记录全部会话的 JSON。不同版本的文件名与外壳字段会变，因此解析器不绑定文件名，而是**按结构识别**：遍历所有 JSON 文件，寻找同时满足「可枚举出会话对象」与「会话内含消息集合」的节点。

### 归一化策略

把三种常见结构收敛到同一个中间形态：

1. **mapping 树**：会话内以节点字典表示，节点含 parentId 与 message，需从叶子回溯到根，还原出线性对话；分支时取当前选中的叶子。
2. **messages 数组**：每条含 role 与 content，按时间或数组顺序直接映射。
3. **chat_messages 数组**：字段名不同（如 content 为对象或数组），需提取文本片段拼接。

```typescript
type RawConversation = Record<string, unknown>;
interface NormalizedMessage {
  role: 'user' | 'assistant' | 'system';
  content: string;
  reasoning?: string;
  createdAt: number;
}
// 入口对任意输入都返回 NormalizedMessage[]，保证下游只有一种形态
```

### id 与时间

- 会话 id 尽量沿用原始 id；缺失时用「标题 + 首条消息时间」做稳定哈希，保证多次导入不产生副本。
- 时间戳兼容秒/毫秒/ISO 字符串三种写法，统一转为毫秒；无法解析时按导入顺序递增补齐。
- 消息 id 用「会话 id + 序号」派生，续聊产生的新消息用随机 id，避免与导入数据冲突。

### 导入流程

1. 用户拖入压缩包或 JSON 文件；压缩包在浏览器内用 JSZip 解压，不上传。
2. 解析器产出归一化结果，界面展示「会话数 / 消息数 / 跳过数」预览，用户确认后写入。
3. 写入在单事务内完成，遇到同 id 会话按「消息并集」策略合并，保留本地更长的分支。
4. 导入完成后自动定位到最新会话，可直接在输入框续聊。

### 续聊的上下文策略

导入的历史消息与本机新消息同库同结构，续聊时无需特殊处理。为控制成本，默认只回传最近 **N** 轮（默认 20 轮，可在设置调整），并对超长单条消息做尾部截断，截断处在界面提示「历史已裁剪」。若用户希望严格延续早期上下文，可在会话设置中改为「全量回传」。

## 界面还原

### 设计令牌

| 令牌 | 亮色取值 | 用途 |
| --- | --- | --- |
| brand | #4D6BFE | 主按钮、选中态、链接、发送按钮 |
| bg / surface | #FFFFFF / #F7F8FA | 页面底色与侧栏、气泡底色 |
| text / muted | #1A1A1A / #8A8F99 | 正文与辅助说明 |
| radius | 12px / 16px / 999px | 卡片、输入容器、胶囊按钮 |
| font | 系统字体栈，字号 14–16px | 中文优先 PingFang / 微软雅黑 |

### 页面结构

- **欢迎页**：居中标题、一句引导、四枚建议胶囊、底部悬浮输入框；不显示空会话列表。
- **会话页**：顶部细导航（返回/标题/更多），消息区单列最大宽度约 760px，用户消息右侧浅灰气泡，助手消息无气泡直接排版。
- **侧栏**：分组按「今天 / 近 7 天 / 更早」，每项单行省略，悬浮出现重命名与删除。
- **输入区**：圆角容器包裹多行输入、左侧附件按钮、右侧发送/停止按钮；空内容时按钮为禁用灰，输入后变品牌蓝。

### 交互细节

- 发送后输入框清空并保留草稿历史，向上箭头可调回上一条输入。
- 消息悬浮出现「复制 / 重新生成 / 删除」，长按在移动端触发同样菜单。
- 流式期间底部显示「停止生成」，点击立即中止并保留已输出内容。
- 滚动遵循「贴底才自动跟随」：用户上滑查看历史时不被强制拉回。

### 响应式与主题

宽度小于 768px 时侧栏转为抽屉，顶部出现汉堡按钮；输入区固定在安全区上方并适配 **env(safe-area-inset-bottom)**。主题通过 **data-theme** 切换 CSS 变量，跟随系统或手动指定，选择结果写设置表。

### 测试策略

- **解析器单测**：用三套脱敏样例覆盖 mapping、messages、chat_messages 三种结构，断言消息条数、角色序列与时间递增。
- **SSE 单测**：构造分块到达的字节流（含跨块断行、中文多字节），断言正文与思考内容拼接正确。
- **端到端**：手工路径清单——首次登录、发消息、停止、重发、导入、续聊、刷新后数据仍在、清除密钥。

## 风险与合规

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 接口变更 | 网页通道接口调整导致 404 或结构变化 | 通道隔离 + 明确错误提示 + 一键切回 API；README 标注实验性 |
| 密钥泄露 | 本机被他人使用或恶意脚本读取 | AES-GCM 加密存储、不可导出密钥、支持一键清除、不在日志中出现 |
| 商标与素材 | 使用官方 Logo、图标、字体造成侵权 | 不使用官方图形资源，图标全部来自开源图标库；README 注明非官方、无关联 |
| 数据丢失 | 用户清理站点数据或换设备 | 导出为 JSON、导入同一格式、设置页常驻备份提示 |
| 计费争议 | 本地估算与官方账单不一致 | 费用一律标注「估算」，真实账单以官方控制台为准 |

## 演进路线

- **一期**：API 通道完整功能、导入与续聊、界面还原、本地加密。
- **二期**：网页通道稳定性、附件与图片问答、提示词库、快捷键。
- **三期**：可选自建同步服务（端到端加密）、多设备增量合并、插件式模型适配器。
