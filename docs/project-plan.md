# DeepSeek API 版 · 项目规划文档

本文档说明「DeepSeek API 版」开源客户端的目标、范围、里程碑与验收口径。读者是项目负责人、开发者和后续贡献者，读完应能明确「做什么、先做什么、怎么算做完、有哪些风险」。技术实现细节见配套的《技术设计文档》。

## 项目概要

### 为什么要做

官方 App 好用，但存在三个真实痛点：会话数据在账号里、导出后只是一堆 JSON 无法继续对话；只能用官方额度，无法走自己已充值的 API 余额；想改造界面或做二次开发没有可用的开源实现。本项目把这三件事一次解决：**登录官方账号、按 API 计费、导入官方导出数据后原地续聊**，并把界面做成与官方 App 一致的使用手感，最终以可直接安装的安卓 APK 形式交付。

### 目标与成功标准

| 目标 | 可验证的成功标准 |
| --- | --- |
| **数据自主** | 官方导出包（本地文件或下载链接）导入后 30 秒内完成，会话数、消息数与源文件一致；导入的会话可以直接继续对话，历史上下文参与生成。 |
| **计费透明** | 每次回答后显示本次输入/输出 token 与费用估算，设置页可查余额；账单口径与官方控制台误差在合理范围内（估算性质已在界面标注）。 |
| **体验一致** | 老用户在没有提示的情况下使用，界面布局、配色、输入区、思考折叠的观感与官方 App 无差异感；核心路径不超过 2 次点击。 |
| **一键可用** | 手机上装一个 APK 就能用；登录既能粘 API Key，也能在 App 内登录官方账号。 |
| **开源可用** | 仓库含完整源码、文档、许可证与贡献指南；任何人 clone 后执行三条命令即可本地运行，APK 由 CI 自动产出并发布到 Release。 |

### 用户与场景

- **重度个人用户**：已有大量官方网页/App 会话，希望统一到一个可备份、可搜索的本地客户端。
- **API 使用者**：已有 API 余额，希望有一个顺手的对话界面，而不是在终端或第三方平台之间来回切换。
- **手机用户**：不想为聊天专门开浏览器，希望桌面有个独立图标、和自己的 API 余额绑定。
- **开发者**：需要一套可读、可改的参考实现，用来做自己的内部工具或二次开发。

典型路径：安装 APK → 打开即登录（粘 Key 或 App 内登录）→ 粘导出链接一键导入历史 → 在某个半途而废的技术问答里接着问 → 看到本轮花了多少 token。

## 需求范围

### 功能清单与优先级

| 模块 | 功能 | 优先级 | 验收口径 |
| --- | --- | --- | --- |
| 登录 | 凭证自动识别（一个输入框） | P0 | `sk-` 与网页令牌都能自动判定通道；无效凭证不入库；`Bearer` 前缀可清洗 |
| 登录 | App 内官方账号登录（安卓） | P1 | 弹出的官方登录页完成登录后自动回填令牌并登录；取消返回不留状态 |
| 登录 | 剪贴板一键填入 | P2 | 有一键读剪贴板并自动提交；无权限时给出提示 |
| 对话 | 流式问答、停止生成、重新生成 | P0 | 首字延迟不劣于官方客户端同条件表现；停止后内容不丢 |
| 对话 | 深度思考内容折叠展示 | P0 | 思考内容与正文互不污染，默认折叠可展开 |
| 会话 | 列表、搜索、重命名、置顶、删除 | P0 | 1000 条会话下搜索响应小于 100ms |
| 导入 | 官方导出包解析与入库（本地文件） | P0 | 三种结构均可解析；重复导入不产生副本 |
| 导入 | 一键链接导入 | P1 | 粘贴导出下载链接即可完成下载、解压、预览、入库；跨域/失效给出可执行提示 |
| 导入 | 导入后续聊 | P0 | 导入会话内可继续提问，历史参与上下文 |
| 计费 | tokens 与费用估算、余额查询 | P1 | 每条回答显示用量；设置页可查余额 |
| 界面 | 还原官方观感、明暗主题、移动适配 | P0 | 320–1440px 宽度下无破版 |
| 数据 | 本地加密、导出备份 | P1 | 密钥不以明文出现在任何存储；备份可再导入 |
| 分发 | 安卓 APK + Release 发布 | P1 | CI 自动出包，可直接安装，Release 页提供下载 |
| 附件 | 图片与文件问答 | P2 | 视模型能力提供，不作为一期验收项 |

### 一期不做

- 账号体系与云端同步服务：一期完全无后端，避免引入合规与运维成本。
- 团队空间、会话分享链接：涉及服务端与权限模型，放到三期。
- 应用商店上架与企业签名：一期只在 GitHub Release 分发调试签名包，正式签名由二次开发者自行配置。
- 多模型市场：一期只支持官方两条模型通道，接口层预留适配器。

## 风险与应对

| 风险 | 等级 | 触发信号 | 应对 |
| --- | --- | --- | --- |
| 网页接口失效 | 高 | 登录后对话报 404 / 结构变化 | 通道隔离，报错即引导切回 API；README 标注实验性，不承诺长期可用 |
| 官方登录页存储变动 | 高 | App 内登录取不到令牌 | 插件只读 `userToken`，取不到则提示改粘贴；两条路径共用同一段校验逻辑 |
| 导出格式变化 | 中 | 解析结果为空或字段缺失 | 结构识别而非文件名识别；保留原始 JSON 供排障；解析失败给出可复现的最小样例要求 |
| 导出链接跨域被拦 | 中 | 链接导入报 CORS / 401 / 403 | 明确提示「需登录 cookie，请先下载再选本地文件」，并保留本地文件入口 |
| 商标与素材争议 | 中 | 仓库被投诉使用官方标识 | 不使用官方 Logo、图标与字体；README 首屏声明非官方、无关联；命名为「第三方客户端」 |
| 浏览器配额不足 | 低 | 写入抛 QuotaExceededError | 写入前估算容量，超限提示导出并清理早期会话 |
| 费用估算偏差 | 低 | 用户反馈与实际账单不符 | 全部标注「估算」；价格表可在设置中改；真实账单以官方为准 |

## 开源治理

- **许可证**：MIT，允许商用与二次开发，降低使用门槛。
- **目录约定**：源码在 src，原生插件在 native，文档在 docs，示例数据不含真实用户内容。
- **贡献流程**：Issue 模板区分 bug / feature；PR 需通过类型检查与构建；提交信息用 Conventional Commits。
- **版本策略**：0.x 阶段小步快跑，破坏性变更写进 CHANGELOG 并在 README 提示。
- **合规声明**：明确本项目与 DeepSeek 官方无隶属关系，凭证与数据只存本地，用户需自行遵守官方服务条款。

## 度量指标

| 指标 | 目标 | 采集方式 |
| --- | --- | --- |
| 首字延迟 | 同网络下不高于官方客户端 20% | 本地埋点计时，开发期手动验证 |
| 导入成功率 | 样例集 100% | 解析器单测覆盖率 |
| 续聊上下文命中 | 导入会话续聊时历史被正确引用 | 端到端手工清单 |
| 登录成功率 | 粘贴与 App 内登录两条路径均能一次成功 | 人工回归清单 |
| 崩溃与白屏 | 核心路径 0 次 | 异常边界包裹 + 手工回归 |

## 交付物与验收

1. 可运行的开源仓库：源码、README（含全部界面截图）、LICENSE、CHANGELOG、Issue/PR 模板。
2. 技术与规划文档各一份，随仓库 docs 目录同步；安卓打包说明单独成篇。
3. 本地构建通过，dist 可直接部署到任意静态托管。
4. 安卓 APK 在 GitHub Release 可下载安装，桌面图标、包名、版本号正确。
5. 验收演示：安装 APK → 登录（两种方式各试一次）→ 粘贴导出链接导入 → 打开其中一条会话 → 继续提问 → 看到思考过程与本次用量。
